# 知能图谱（PKA Graph）· 个人知识建模系统

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

**第一次使用？** 读 [docs/从零开始-建立你自己的知识库.md](docs/从零开始-建立你自己的知识库.md)
——10 分钟：获取程序 → 启动 → 建立自己的知识库 → 投递材料 → 测验 → 接 Notion。
Windows exe 在 [Releases](https://github.com/banana-Hu/pka-graph/releases/tag/v1.0.0)。

**多实例**：每个实例 = 一个知识库 + 一个端口。在程序目录建
`instance.local.json`（gitignored）声明你的日常库：

```json
{ "vault": "D:\\MyNotes", "allow_real_vault": true, "port": 8765 }
```

`python server_start.py` 即接管；默认（无此文件）启动内置 `test_vault`（8765）。

独立程序协作开发入口：[统一任务接口与协作约定](docs/独立程序统一任务接口与协作约定.md)（任务核心与主程序接线已落地，真实链路未验收）。

当前版本实施与运行说明：[个人知识库长期运转实施方案](docs/个人知识库长期运转实施方案.md)。

2026-10-05 新增统一任务模式：完整冻结原件 → 分段分析 → 中文精华笔记 → 完整性验证 → AI 自动审核（最多两轮修订）→ 仅新增入库 → 可选 Notion。用 `PKA_TASK_PIPELINE=task` 启用；`continuous_start.py` 的监督子进程固定采用任务模式。既有普通启动保持 legacy 兼容。

默认不启用状态镜像。AI 审核通过不等于用户掌握，新增节点仍 untested。审核模型未配置、审核失败或来源不完整时不入正式区。以下历史说明中“原文混排”“免审核直推”“Obsidian 自动镜像”的表述不适用于当前 task 模式，以本段和实施方案为准。

把 Obsidian 知识库接入为**可测验、可复习、可持续生长的个人知识图谱**：
知识节点带掌握状态（绿/红/蓝三色显示在 Obsidian 原生图谱），AI 帮你把材料
整理成中文知识笔记直接入库，测验通过才进入掌握层，间隔复习对抗遗忘。

## 一、整体架构

```
                      ┌────────────────────────────────────────────┐
   信息来源            │           知能图谱服务（本机，双实例）        │
                      │                                            │
 Obsidian 知识库 ──只读扫描──▶ │ ① 材料接收      收件箱监听（30s 轮询）    │
 (8 篇笔记已接入)      │ ② 语义分析      MiniMax-M2.7 + 摘录定位校验 │
 收件箱投递 ──────────▶ │    （用户上传 / 智能体投递 / 上游候选池）    │
 (个人学习状态/inbox/) │ ③ 笔记加工      Skill 日期版本路由 + 分段提取 │
 AI 信息获取项目 ──候选池──▶ │ ④ 自动入库      免逐条审核，一个动作直推     │
 (RSS/搜索/抖音热榜)   │ ⑤ 测验复习      AI 出题判定 + 间隔复习       │
 智能体（mesh 9 个）──投递──▶ │ ⑥ 元数据服务    state.json 权威状态         │
                      └──────────────┬─────────────────────────────┘
                                     │ 镜像 mastery_status 一个字段
                                     ▼
                        Obsidian 图谱三色（graph.json colorGroups）
```

## 二、核心链路（材料 → 知识 → 掌握）

```
投递（收件箱文件）
  → 稳定性检测（两次扫描大小不变）→ 内容哈希去重 → 溯源解析（front-matter）
  → 语义分析（MiniMax-M2.7；判定 + 摘录逐字定位，定位失败自动降级）
  → 判定分流：
      new_node / supplement / revision → 自动入库（免逐条审核，2026-10-03 起）
      uncertain / news_only / duplicate / insufficient → 只留流水，不进库
  → 内容准入（机器质量门槛，免人工审核不豁免）：
      publishable = 加工成功 且 内容完整（无缺节/无未处理范围）且 取得原文全文
      且 正文通过可用性评估（目录/课程大纲/摘要/元信息级不达门槛）
  → 自动入库（一个动作直推）：
      达标 new_node：读来源全文 → Skill 加工（逐节：代码插入逐字原文 + 模型写
                第一人称笔记）→ 写入 {领域}/正式笔记/（status: accepted）→ 建节点（untested）
      未达标：自动路径留队（暂时性故障按退避重试；材料不足不自动重试）；
              人工接受则降级为 {领域}/候选笔记/ 线索笔记（不建节点）
      supplement：直接补充进已有节点（不产笔记）
  → 用户测验（AI 出题，通过条件回答前冻结）→ passed/failed
  → 间隔复习（7/21/45/90 天，通过推进、失败重学）
```

三条不变的原则：
1. **内容入库 ≠ 掌握**。AI 自动入库的节点一律 `untested`；`passed` 只能由测验产生。
2. **摘录必须逐字存在**。模型引用原文回查定位，编造即降级为"不确定"。
3. **不确定就说不确定**。`uncertain` 不入库；未读完的材料带"未读完标注"。
4. **免审核不豁免质量门槛**。摘要/目录/元信息级材料只作线索，不因免审直推变正式笔记。

## 三、模块清单（`pka_graph/`）

| 模块 | 职责 |
| --- | --- |
| `store.py` | 权威状态：原子写 + 乐观锁 + 备份 20 份 + 路径硬限制；**读写分离**（safe_read_path 只校验路径；写保护——真实库白名单目录仅新建——仅作用于写侧） |
| `models.py` | 节点/关联数据契约与整体校验 |
| `service.py` | 节点 CRUD、合并/拆分/归档、图谱视图、**笔记关联解析**（移动/重命名后按稳定 ID 回查；重复 ID → ambiguous；解析只读不写状态） |
| `quiz_service.py` / `quiz_model.py` | 掌握测验：会话状态机（防伪造）+ 模型适配器 + **取材感知**（缺失/截断/空正文逐项报告；取不到正文即终止出题，不静默降级） |
| `review_service.py` | 间隔复习：排期、到期分组、暂停/补排 |
| `discovery.py` | 知识发现：预筛、语义复核、**内容准入与单动作直推**（自动/人工双路径）、重试分级（暂时性故障退避 / 材料不足不自动重试）、崩溃恢复（正式+线索双意图日志） |
| `discovery_model.py` | 发现语义分析适配器（独立预算 24/日） |
| `note_processor.py` | 单文件全文笔记加工：Skill 路由 + 全部分段提取 + 汇总成文（不设调用额度，逐次记账） |
| `inbox.py` | 收件箱监听：稳定性/去重/溯源/**自动入库**（退避重试、状态可见） |
| `mirror.py` | 状态镜像：测验结果写回笔记 front-matter（唯一触碰笔记的通道） |
| `scanner.py` / `frontmatter.py` | 只读扫描（路径定审核状态）+ 受限 front-matter 解析 |
| `ext_access.py` | 外部 AI 只读接口（`PKA_EXT_TOKEN`，当前未启用） |
| `content_fetcher.py` | 受控原文获取（本地限库内 / 公开 URL 带 SSRF 防护） |
| `local_config.py` | `ai.local.json` 加载（密钥不复制、不落盘） |
| `server.py` | HTTP 服务与全部路由（单实例保护） |
| `知识库入口.py`（根目录） | 人类操作主入口：桌面客户端窗口，选文件 → 进入知识库 → 自动入库 |

Skill 目录：`skills/mastery_quiz/`（测验判定规则）、`skills/note_processing/`
（笔记加工规范，`{日期}-{领域}.md` 命名，总路由每次取最新一版）。

多智能体协作契约见 **`智能体协作手册.md`**（投递格式、硬边界、范围清单）；
使用者视角的完整操作说明见 **`使用指南.md`**。

## 五、安全边界

- 写入前整体校验，失败即拒绝；单文件原子替换；乐观版本锁；`request_id` 幂等。
- 每次写状态前自动备份（保留 20 份）；损坏恢复不覆盖损坏原件、启动遇损坏拒绝启动。
- 真实库受控写：`--allow-real-vault` 显式开启；可写范围 = 管理区 + 「正式笔记/」「候选笔记/」
  子树（**仅新建，绝不覆盖已有文件**）；读取走独立的安全读取入口（只校验路径，无写保护）。
- 状态镜像**独立授权、默认关闭**（`PKA_MIRROR_STATUS=1` 显式开启）：关闭时测验判定、
  节点状态与复习安排照常维护，只是不改笔记文件；开启后也只改 `mastery_status` 一个字段。
- 密钥只经 `ai.local.json` 指向的 env 文件进入内存，不入代码/日志/生成物。
- 预算：发现 24 次/日、测验每会话 6 次；笔记加工不设每日/单篇调用额度，实际请求仍逐次记账。旧 `PKA_NOTE_DAILY_LIMIT` / `PKA_NOTE_MAX_CALLS` 不再缩减生产笔记范围。
- 单文件全文规则（2026-10-04）：PDF 不设页数/字符上限，上传与文件读取不设字节上限；每次只处理一个文件，不合并多文件，收件箱/发现/加工串行。发现模型生产配置固定全文输入，旧 `PKA_DISCOVERY_MAX_INPUT_CHARS` 不再缩减范围；显式受限适配器输入不足时明确失败而非发送前缀。笔记按 4000 字符分段是请求组织方式，不限制全文长度或分段数。
- 应用取消额度不等于模型有无限上下文或机器有无限内存；超时、有限重试、来源/引文校验、权限边界保留。模型报告 `finish_reason=length` 时明确失败，不把截断返回当作完成。

## 六、产品规则（测试锁定）

1. 节点状态只有 `untested / failed / passed`；层级由状态推导（passed=掌握层）。
2. 新建/导入/自动入库/合并/拆分一律 `untested`；改范围需确认后回 `untested`。
3. 笔记审核状态（accepted）与节点掌握状态相互独立、互不触发。
4. 同名不同范围可共存（唯一性靠稳定 ID）；`request_id` 幂等防重复。
5. 管理界面没有"直接标记通过"按钮；通过只能来自服务端模型判定。
6. 复习：首次通过排首档；到期通过推进一档（90 天封顶）；失败清计划进"待重学"；
   用提示 = 辅助学习不改状态；应用关闭时不主动通知。
