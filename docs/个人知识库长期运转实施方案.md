# 个人知识库长期运转实施方案

本文给使用者和开发者说明本轮补齐的目标、运行方式和验收条件。用户在 2026-10-05 明确要求电脑本地持续运行，并由 AI 自动审核笔记，不再逐篇人工审核。

## 目标与运行链路

个人记录和外部 Agent 都投递到同一知识库。已有上游采集系统按批准来源取得材料，知识库根据已有节点分析知识增量，再使用加工 Skill 完整处理单文件，生成中文、结论先行的个人理解式笔记；另一次 AI 审核核对原文支持、机制解释、遗漏和表达，再决定自动收录。跨学科研究方向规划器不是本轮已经实现的能力。

链路为：来源收集 → 冻结原件 → 正文提取 → 知识增量分析 → 笔记生成 → 完整性校验 → AI 审核 → 仅新增入库 → 可选 Notion 同步。

AI 审核通过表示符合收录要求，不表示所有事实已独立证实，也不表示使用者已经掌握。已有笔记保留；新增节点保持 untested。镜像默认关闭。

## 本地长期运行

- 主服务常驻，统一队列串行处理重任务；没有新内容时等待，不反复调用模型。
- 已批准的上游采集系统继续负责 RSS/搜索；知识库只接可用的来源适配器，不启动邮件、日报或其他无关任务。失败来源单独退避，不拖住整个队列。
- 周期任务使用可中断等待，记录下一次执行与最近成功时间，避免重复锁/重复线程。重新联网或从睡眠恢复后补一次检查，不补跑每个错过时刻。
- 独立运行入口提供进程监督、有限自动重启、停止标记和健康记录。Windows 启动注册与日常运行解耦，允许明确启用/停用；注册命令保存准确 vault/port，不偷偷回到测试库。
- 24 小时运行要求电脑开机、未睡眠、网络和模型服务可用。锁屏不等于关机；睡眠、断电期间不能继续工作，恢复后根据持久任务补跑。程序不自动改系统电源计划。
- 本轮先实现并用合成材料/假模型验证；不以短期测试声称已完成 24 小时稳定性验收，不启动无限真实模型调用或更改既有自启项。

## AI 自动审核

- 必须实际调用审核模型，不能用长度/关键词规则冒充语义审核。可复用现有服务商，但独立审核角色、提示词、调用记录和结论。
- 审核输入包括本篇原文（可分段全文覆盖）、生成笔记和所用 Skill；有关节点用于前面的增量分析。审核不默认读取或改写使用者已完成的笔记。
- 检查贡献是否源于原文、解释是否抓住机制、关键限制是否丢失、是否第一人称理解而非介绍材料、是否结论先行、是否塞入大量案例/操作步骤/迁移建议。
- 通过则自动入库；需修正则将明确问题交回生成器，最多两轮修正。超过上限保留候选并标记原因，不循环消耗；无法判断或缺原文则阻塞，不默认为通过。
- 不要求人工逐篇审核。界面只展示通过/修正中/未通过/缺资料等结果，使用者可抽查和修改 Skill。

## 开发分工与最小实施

Codex 负责统一任务接口/持久账本、并发安全、取消/重试/恢复、加工与提交分离、笔记规范、审核入口和运行规则。ZCode 负责适配器、主服务路由/生命周期、收件箱单一调度入口、桌面状态和长期启动调用。新增 review 阶段位于 validate 和 commit 之间；双方以公共接口约定为准，分文件开发。

优先修复现有定时重复锁、StateStore 写事务、Notion 锁/归属；复用现有解析、模型和图谱，不新增第二个知识库，不扩大 UI 开发。

## 可靠性与成本

冻结输入后按哈希恢复，阶段成果和分段检查点持久保存。入库/同步失败只重试相应步骤，不重新生成整篇笔记。网络与限流有限退避；认证/配置错误停等配置；账本损坏保留原件并停止写入。

完整单文件处理无统一字数/页数上限；并发和失败重试有界，正文超出模型上下文时完整分段和分层合成。没有新内容不调用模型；同内容/同 Skill/同模型版本复用已核验成果。

取消与本地提交共享原子边界。Notion 请求结果未知时先核实归属，禁止盲目重复发布。日志仅记录任务与错误类别、产物位置，不复制密钥和完整私人正文。

## 验收

离线验证必须包括：一个文件完整生成并自动审核入库；审核拒绝不入库；审核未配置不假通过；网络重试有上限；恢复不重复生成/入库；取消无迟到提交；两个写入不丢更新；定时检查实际执行；同源重复不烧模型；关闭后不继续运行；旧入口兼容；非本人任务不可控制。

交付时分别报告已实现代码、离线测试、主程序联调和真实运行未验证项。真实模型语义质量与 24 小时运行另以实际记录验收，不用“打包成功”替代。

## 本轮实现与一次性启用

已实现持久任务账本、唯一工作线程、完整单文件分析/加工/审核检查点、有限重试、取消、入库意图恢复、AI 审核两轮修订、只新增正式笔记、桌面与 HTTP 任务入口、独立长期监督入口和登录后自启命令。没有重写 Web 图谱。

首次启用只需配置一次，不是逐篇人工审核：

1. 在现有 `ai.local.json` 指定的密钥文件填好密钥。现有加载器将同项目服务接入分析、加工和独立审核角色，不复制密钥；也可独立配置 `PKA_REVIEW_*`。不要把密钥发到聊天或提交 Git。
2. 在现有发现设置开启周期检查（例如 60 分钟），需要下载公开原文时明确开启远程获取。默认关闭的功能不会因开机被偷偷开启。已有上游采集系统也必须持续更新候选池；本知识库没有替它启动采集守护或日报邮件。
3. 从本项目运行以下命令。首次先用测试库；正式库需显式 `--allow-real-vault`，仅新增笔记和管理状态，原有笔记不改。启用与自启注册本轮都没有实际执行。

本地文件只接受授权输入目录内的路径；需要投递下载目录等外部文件时，用 `PKA_TASK_INPUT_ROOTS` 明确列出目录（分号分隔），不自动授予整个磁盘的读取权限。新增知识自动入库，补充/修订旧笔记仅留建议，不越权改写旧正文。

```powershell
python continuous_start.py --vault "<你的知识库路径>" --port 8766 --allow-real-vault
python continuous_start.py --vault "<你的知识库路径>" --status
python continuous_start.py --vault "<你的知识库路径>" --stop
```

登录后自启用同一完整启动参数再加 `--install`；撤销仅加 `--uninstall`。监督器不修改电源计划，电脑睡眠期间不能采集。严重不可确认的写入停止并保留现场，不让 AI 以“审核通过”掩盖工程失败。

本轮没有新增跨学科研究方向规划器、转写 worker，也没有重新打包 EXE。它们不是本次“队列—AI 审核—安全入库—长期运行”完成的证明；论文/课程的来源质量、真实模型误判率和连续运行稳定性仍要独立验收。
