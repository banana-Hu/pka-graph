# 资料拓展方向 · 后续契约（未实施，仅记录）

> 状态：**未实施**。本文档只记录用户确认的拓展方向与边界，作为后续开发契约；
> 任何一条落地前需用户再次确认。云端（Notion）、Web 界面扩建本轮均不接通。

## 拓展的四个方向（围绕当前实际问题或项目）

系统在寻找新材料时，结合已有知识节点，优先寻找：
1. **能串联已有案例的底层原理**——多个孤立节点背后共有的机制；
2. **能解释架构与运作逻辑的材料**——讲清"为什么这样设计"的原始正文；
3. **能修正旧认识的边界与反例**——挑战或限定既有结论的证据；
4. **相邻领域和技术的新机制**——与已有节点相邻、可迁移的方法。

## 检索与措辞边界（硬约束）

- **先检索库内，再找外部原始正文**；库内已覆盖的不再外找。
- 不把"检索没命中"说成"用户不知道"（字段 `retrieval_missed`，措辞：
  "本次检索未命中已有节点，待确认（不代表知识不存在）"）。
- 不把"最近发布"直接当成"有知识增量"——发布时间与知识价值无关。
- 不强制前置课程：难材料先提供可读原文，按需补解释。
- 跨领域联系只用于**选材**，不强行写进每篇笔记。

## 产出与流转

- 拓展材料走现有准入管线：取得原文全文 + 加工完整 → 正式笔记；
  摘要/线索级 → 线索队列，不冒充完整。
- 掌握状态由测验独立产生；收集、加工、发布均不改变掌握状态。
