# 笔记加工 · 总路由

本目录存放"完整中文笔记加工"环节的提示词 Skill。路由规则（由 `pka_graph/note_processor.py` 的 `NoteSkillRouter` 执行）：

## 文件命名与版本

```
{YYYY-MM-DD}[-{序号}]-{种类}.md
```

- **文件名日期与可选序号构成版本号**。同日调整递增序号，不覆盖旧版。
- 每次加工只采用该种类日期与序号最新的一版；旧版本保留作历史追溯。
- 每次加工会把所用版本号写入笔记 front-matter 的 `note_skill_version` 字段与建议记录，可审计。

## 种类与回退

- 种类 = 材料所属领域（如 `AI技术`、`产品`），取自建议关联节点的领域；
- 该领域的版本不存在时**回退到「通用」**；
- 连「通用」都没有 → 加工失败（如实报错，不降级到无规范输出）。

## 惯例

- 提示词用中文书写；笔记标题与小标题也以中文为主。英文原始标题保留在原文里，不能直接充当笔记显示标题；机器标识、代码、必要专有名词保留原文。
- 笔记从记录者自己的理解出发，不用“相对于你”“建议你”等第三方对话措辞；第一人称不等于可以编造个人经历或已掌握状态。
- 规范必须包含：中文标题要求、总分结构（核心结论/机制依据/步骤例子边界/来源与待确认）、
  诚实性要求（只用材料内的要点与逐字摘录、未读完如实标注、拆分只建议不执行）。
- 规范调整需人工批准（与 classify/segment 配置同级）。

## 单文件全文与预算规则（2026-10-04）

- 每次只处理一个来源文件；同一服务实例的收件箱、发现与笔记加工串行执行，不混合多个文件产出同一篇笔记。
- 读取不设页数、字符或字节上限；笔记加工不设单篇/每日调用额度，保留实际用量账本。旧预算环境变量不再缩减正文处理范围。
- 分段只是完整处理单文件的方法，所有分段都必须处理；不能只处理前九段，不用单个巨大请求替代必要分段。
- 发现模型默认接收完整单份材料，不能只发前5000字符，也不把5000替换为另一个静默截断值。若显式输入限制或模型实际容量不足，明确失败，不假装全文已读完。
- 这些规则不取消超时、有限重试、引文校验、候选审核、只读/新增权限，也不授权自动重试失败论文。

## 当前实现边界

此文件是路由规则说明，当前 Python 不会把它作为独立模型提示词读取。实际传给模型的是选中的日期版 Skill。
目前领域取自关联节点，缺领域版回退通用；这不是模型理解材料后完成的领域分类。领域语义路由尚待实现，不能把文件版本选择冒充知识判断。
